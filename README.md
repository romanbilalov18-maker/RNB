# RNB — виртуальный торговый бот

RNB — Python-проект для анализа рыночных данных T-Invest, формирования торговых решений и моделирования сделок в виртуальном портфеле. Состояние портфеля и журнал решений хранятся в SQLite.

> **Важно:** проект предназначен для тестирования и исследования стратегии. Не считайте результаты виртуальной торговли прогнозом будущей доходности. Перед использованием реальных средств необходимы отдельные проверки рисков и поведения системы.

## Возможности

- Получение рыночных данных через T-Invest SDK.
- Анализ инструментов и формирование рекомендаций BUY/SELL.
- Виртуальное исполнение сделок с учётом комиссий и ограничений позиции.
- Хранение виртуального портфеля в `data/virtual_portfolio.sqlite3`.
- Журнал решений и последующая оценка исходов в `data/decision_audit.sqlite`.
- Автоматические unit-тесты через GitHub Actions.

## Требования

- Python 3.11
- Токен T-Invest для доступа к рыночным данным
- Доступ к сети для установки SDK и работы с API

## Установка

Клонируйте репозиторий и создайте виртуальное окружение:

```bash
git clone https://github.com/romanbilalov18-maker/RNB.git
cd RNB
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

В Windows активируйте окружение командой `.venv\\Scripts\\activate`.

## Настройка

Установите переменные окружения. Не записывайте токены в исходный код и не коммитьте их в Git.

Linux/macOS:

```bash
export INVEST_TOKEN="ваш_токен"
export VIRTUAL_INITIAL_BALANCE="10000"
export VIRTUAL_COMMISSION_RATE="0.0005"
export TAKE_PROFIT_PERCENT="0.15"
export VIRTUAL_PORTFOLIO_DB="data/virtual_portfolio.sqlite3"
```

| Переменная | Назначение | Значение по умолчанию |
|---|---|---:|
| `INVEST_TOKEN` | Токен T-Invest; обязателен | — |
| `VIRTUAL_INITIAL_BALANCE` | Начальный виртуальный баланс | `10000` |
| `VIRTUAL_COMMISSION_RATE` | Комиссия в долях единицы | `0.0005` |
| `TAKE_PROFIT_PERCENT` | Порог Take Profit в процентах | `0.15` |
| `VIRTUAL_PORTFOLIO_DB` | Путь к БД виртуального портфеля | `data/virtual_portfolio.sqlite3` |
| `DECISION_AUDIT_DB` | Путь к БД аудита решений | `data/decision_audit.sqlite` |
| `RUN_DURATION_MINUTES` | Продолжительность запуска | `60` |
| `CYCLE_INTERVAL_MINUTES` | Интервал между циклами | `5` |

Значения комиссий задаются как доля: `0.0005` соответствует 0,05%. Параметр Take Profit задаётся в процентах, а не в долях.

## Запуск

```bash
python -m bot.main
```

Для ограниченного тестового запуска можно задать длительность и интервал:

```bash
RUN_DURATION_MINUTES=10 CYCLE_INTERVAL_MINUTES=2 python -m bot.main
```

Команда запуска использует виртуальное исполнение сделок. Не запускайте длительные тесты, пока не проверили настройки, доступность API и поведение на тестовых данных.

## Тесты

Unit-тесты должны работать без реальных запросов к брокеру:

```bash
python -m unittest discover -s tests -p "test_*.py" -v
```

Для live smoke test в GitHub Actions требуется секрет репозитория `INVEST_TOKEN`. Запускайте его вручную только когда понимаете длительность выполнения и последствия обращения к API.

## Данные и безопасность

- Не добавляйте `.env`, токены, ключи или персональные данные в коммиты.
- Перед очисткой файлов SQLite сделайте резервную копию: в них может храниться состояние виртуального портфеля и история аудита.
- Результаты аудита зависят от качества и полноты рыночных данных. Проверяйте неполные котировки и сообщения об ошибках, прежде чем интерпретировать статистику.
- Успешное прохождение unit-тестов не доказывает прибыльность стратегии и не заменяет тестирование на исторических данных и вне обучающей выборки.

## Структура

- `bot/main.py` — основной цикл запуска.
- `bot/config.py` — чтение и проверка конфигурации.
- `bot/paper_executor.py` — виртуальное исполнение сделок.
- `bot/decision_audit.py` — журнал рекомендаций и оценка исходов.
- `bot/intelligence/` — анализ и формирование торговых решений.
- `tests/` — автоматические тесты.
- `.github/workflows/tests.yml` — запуск unit-тестов и ручной live smoke test.
